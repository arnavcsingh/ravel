# Benchmarking Ravel

## Local controlled suite

Run `pnpm benchmark` or `pnpm benchmark --repetitions 5`. This is a **local synthetic benchmark, not an official AsynCodeBench score**. It uses the same scripted generators, inputs, three agents, and controlled ordering in OFF, Observe, and Guard modes.

OFF uses ordinary files without a coordinator or SQLite. Observe records and detects hazards but does not repair them. Guard rejects stale candidates and reruns the same backend generator from fresh input. The downstream generator then reads the published API.

Six scenarios cover overlapping contract migration, a numeric conversion change, serial execution, an identical write, content reversion (A→B→A), and a new invalidation after reversion (A→B→A→C). Three are deliberate races and three are controls. No timing sleep determines the order.

The independent evaluator executes both generated JavaScript artifacts against positive, negative, and zero inputs and compares them with the requested final contract. Task success requires both checks to pass. A stale implementation must fail even if Ravel reports no hazard. Invalid or nonterminating code fails evaluation.

Each run saves `report.json`, `report.md`, generated files, and Observe/Guard SQLite traces below `.ravel/benchmarks/<timestamp>/`. One warmup trial per mode is excluded. Measurement order rotates across modes. The command returns nonzero if expected correctness, hazard counts, or rejection behavior regress.

Metrics include success rate, dependency pass rate, detected hazards, rejected writes, reruns, generation calls, generated bytes, and median runtime. OFF hazard counts are unmeasured. Tokens and token overhead are unavailable because these are scripts, not model calls. Runtime includes coordinator/SQLite setup and recording but excludes fixtures and evaluation. These tiny workloads do not estimate overhead for real coding agents.

## Official AsynCodeBench

Upstream: https://github.com/KaituoZhang/AsynCodeBench

Inspected revision: `566c32b6f4ad209ecfe95f10970b02d4b79289c1` (v0.4.1; its release-status command reports stable).

The upstream runner requires Linux x86_64, Docker, Python 3.12, uv, the pinned OpenHands SDK, and a model endpoint for scored coding runs. Its custom adapter owns assignment execution; the harness retains private worktrees, scope validation, integration, dependency probes, and final evaluation. Ravel's shared-workspace synthetic suite does not implement those official protocols.

The downloaded source and isolated tools live under `.ravel/benchmark-source/` and are ignored by Git. No model credentials are included or required for local tests.

The wrapper uses Bash on Linux and the default WSL distribution on Windows. Set `RAVEL_WSL_DISTRO` to select a different Windows distribution. Set `RAVEL_UV` to an installed Linux uv binary on a fresh machine; this machine has a workspace-local uv installation.

```sh
pnpm benchmark:upstream setup
pnpm benchmark:upstream check
pnpm benchmark:upstream runner-check
pnpm benchmark:upstream dry-run
pnpm benchmark:upstream smoke
```

`setup` downloads the pinned checkout and dependencies; it does not configure a model. `check` runs release validation and selected release/admission contract tests. `runner-check` checks SDK source/version consistency, event roundtrips, and adapter/CLI tests. `dry-run` configures all five protocols for cachetools without model calls. `smoke` uses the upstream diagnostic adapter in a real container; it requires Docker but no model and intentionally does not solve the task. Logs are saved below `.ravel/benchmark-source/reports/`.

These commands exercise the upstream runner. They do not yet inject Ravel into the upstream OpenHands coding tools or implement an official Guard comparison across private worktrees. That adapter must preserve the benchmark's observation, communication, budget, and scope rules before any official OFF/Guard claim is valid.

## Measured local result — 2026-10-03

Five repetitions of six scenarios in each of three modes produced 90 measured trials, excluding three warmups. All expected outcomes matched.

| Mode    | Success | Dependency pass | Detected hazards | Rejections / retries | Median runtime |
| ------- | ------: | --------------: | ---------------: | -------------------: | -------------: |
| OFF     |     50% |             50% |       Unmeasured |                0 / 0 |        1.63 ms |
| Observe |     50% |             50% |               15 |                0 / 0 |       66.16 ms |
| Guard   |    100% |            100% |      0 committed |              15 / 15 |       72.69 ms |

This demonstrates the expected effect on deliberately constructed races, not general coding capability. The report is saved at `.ravel/benchmarks/2026-10-03T19-40-14.594Z-53372/report.json`. Timing is machine-specific and includes durable recording costs.

The official container smoke is currently blocked because Docker's CLI reports that Docker Desktop WSL integration is unavailable for Ubuntu-22.04. Enable that integration before retrying `smoke`. A scored coding run additionally requires a model endpoint and the Ravel-specific mediation adapter described above; no scored official run has been performed.

Official scores must come from an unmodified upstream evaluator and admitted run bundle. A diagnostic adapter smoke can verify wiring but intentionally does not solve tasks. Configuration dry runs, source validation, and synthetic results must not be presented as official success rates.
