# Polyglot migration

Baseline: `077f277`, preserved on branch `ravel`. Migration branch: `codex/ravel-polyglot`.

The baseline has 35 passing tests: 19 core, 3 projection, 3 HTTP, 3 lifecycle, and 7 synthetic benchmark tests. TypeScript checking and formatting pass. React is retained without a rewrite. No provider or further AsynCodeBench integration is in scope.

## Responsibility boundaries

- Go owns concurrency, immutable versions, captured observations, transactional SQLite persistence, blobs, workspace recovery, stale detection, provenance, projections, HTTP and SSE.
- TypeScript owns the existing React/Vite UI and its validated DTO contract.
- Python owns external agent clients, optional provider interfaces, and benchmark orchestration. It uses the same HTTP boundary as other runtime clients; it does not duplicate concurrency decisions.

## Preservation gates

Before removing the TypeScript runtime, equivalent Go tests, cross-language golden replay checks, and all seven Python benchmark tests passed. Golden fixtures were generated by the unchanged baseline runtime before removal. They cover Observe, Guard, repair, every-sequence historical snapshots, exact diffs, focused replay, immutable contents, and the held-intent state. The previous source remains recoverable on `ravel`.

Go tests cover no-ops, own-write frontier, rereads, fresh attempts, A→B→A→C, multiple stale inputs, tombstones, search/list/commands, exact-base patches, captured intent immutability, one pending mutation, gates outside the mutex, concurrent generations, command lock release, materialization failure/recovery, injected SQLite rollback, invalid identities/paths/DAG edges, lifecycle leases/reset and APIs/SSE. Python drives all six benchmark scenarios through Go HTTP and independently executes the materialized artifacts.

The Go race detector passes on Windows with the installed GCC toolchain. SQLite stays embedded with the same normalized schema and immutable event triggers. The pure-Go SQLite driver avoids requiring a native addon for ordinary builds.

## Intentional boundary changes

- React components and shared DTO schemas are retained; only the displayed version label, Vite proxy configuration and package metadata are updated.
- Python uses HTTP; benchmark elapsed time now includes transport overhead and excludes process startup. Compare correctness and generated work across migrations, not millisecond ratios.
- A small JavaScript pnpm bootstrap locates Python. Bash remains only the existing pinned upstream environment bootstrap, called by Python.
- Go's scripted demo/heuristic are local conformance fixtures. No Gemini, Fetch, SpacetimeDB or further AsynCodeBench integration was added.
- `.ravel/v3` is the new default; old data is preserved. A sibling lease remains stable across reset renames.

## Final verification

- 30 Go unit/integration tests, including golden replay, pass; race detector and `go vet` pass.
- Eight Python tests cover benchmark parity and actual process restart/reconstruction/archive reset.
- Four frontend DTO tests, TypeScript checking, formatting and the production build pass.
- Browser: existing React UI renders the Go snapshot, exact schema diff and graph; focused replay works; repair retains the historical two-version branch; live Observe hold/release detects one incident/two affected heads; Guard rejects one candidate and retries with clean heads.
- Vite development mode also passes live hold/release and SSE refresh through its Go API proxy.
- Synthetic benchmark: 90 measured trials, zero mismatches; OFF/Observe 50%, Guard 100%, 15 rejections and retries. See `BENCHMARK.md` for report provenance and timing scope.
- Matched all 90 trials against the saved TypeScript baseline on success, dependency pass rate, hazards, rejections, reruns, generation calls and generated bytes: zero differences across 630 comparisons.

Migration is committed only after the complete app is green. Existing branch checkpoints remain intact.
